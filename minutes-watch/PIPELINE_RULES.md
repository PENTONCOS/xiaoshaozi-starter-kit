# 会议音频流水线交付规则（2026-10-27 用户追问后定）

## 交付物（缺一不算完成）
1. **会议总结**（面向人读的结构化纪要：一句话结论 / 问题或议题 / 方案 / 待办 / 存疑）
2. 逐字稿（带时间戳 + 说话人真名或编号）
3. 声纹匹配分数（含次高候选，跨会验证时必列）

流水线脚本本身只到「逐字稿 + 声纹」；**第 4 步「写总结」必须由助手读逐字稿后完成并把正文发到群里**，不能只发完成卡片。

## 顺序
转录 → 聚类 → 声纹识别 → **写总结并推送（render-minutes.mjs 出卡片）** → 音频处理（见下）

## 硬约束
- 总结只写逐字稿真实出现的内容；ASR 专有名词不确定的标「?」并列入存疑，不补猜
- 说话人未确认时用编号；混合簇不出名字
- 完成卡片 ≠ 交付；卡片之后必须有正文纪要

## 2026-10-27 事故后追加（本场：元化/恨少/出九）
1. **用户给了人数，必须强制 `--speakers N`**，不用自动定人数。自动版靠 MIN_SHARE=0.15 否决小簇，会把话少的人静默并入别人簇（本场 k=3 silhouette 0.151 优于 k=2 的 0.1229，却因第三簇仅 10.1% 被否）。
2. **并簇 → 平均向量 → 高假阳性**：混合簇对未参会者给出 0.70 / 0.58 双双过阈值。结论：阈值管不了混合簇，必须先把簇切干净。
3. **"双高疑判"是必要但不充分的防护**：本次出九簇只有第一名过阈值（0.6405，次高 0.4847），双高规则拦不住。真正拦住它的是发现"婉辞对两个不同人同时给高分"。
4. **向量可信度自检**：一个人在单场里对两个不同簇都给高分 → 该声纹本身有问题，停用（`disabled: true` + 原因），不要靠调阈值。
5. **入库前置条件**：簇必须干净（次高明显低）+ 人名已被用户确认。混合簇、外部人员一律不入库。
6. **排除法归属要标注**：N 人里 N-1 个已确认，剩下的按排除法给名字，但必须在逐字稿头部写明"非声纹结果"。

## 2026-10-27 追加：交付形态（用户点名要求）
1. **纪要必须走渲染器，不得手写纯文本**：`node render-minutes.mjs <data.json> --send <chat_id>`；
   产出 `data.md` + `data.card.json`，卡片含元信息行 / text_tag 关键词 / 一句话结论 / ✅决议 / 📌待办(owner+status) / 🗂议题(带时间戳) / ⚠️风险 / 🧭解读 / 逐字稿路径。
2. data.json 字段：title, date, duration, attendees, transcriptPath, keywords, caveat, tldr[], decisions[{text,note}], actions[{action,owner,due,status}], topics[{title,points[]}], risks[], analysis[], nextMeeting。
3. status 取值映射：open=待跟进(橙) doing=进行中(蓝) done=已完成(绿) block=阻塞(红) risk=风险(红)。
4. **决议必须是会上真出现的「决定」，不是我从讨论里归纳的结论**；归纳内容放 🧭解读。若确无决议，decisions 写「无正式决议」并说明。
5. 提示：卡片正文上限 CARD_LIMIT=26000，议题过多需压缩。

## 2026-10-27 追加：声纹库现状与验证铁律
1. **库内状态**：启用 = 元化、恨少、金桔、出九；停用 = 婉辞（原向量对两个不同人给 0.6151/0.6405，待重录）。
2. **库内向量两两最大相似度 0.485**（元化↔出九），低于阈值 0.55 —— 库本身是可分的。
3. **铁律：不能用「入库所用的那场录音」做验证**。同场音频里不同的人簇间相似度可达 0.58–0.75（本场 元化↔出九 0.7473），拿去测本场入库的向量必然虚高、必然触发歧义。验证必须换一场录音。
4. `build-samples` 已改为与 `identify` 同法（该簇全段平均）；试听片段的裁剪仍走最长段，只影响音频不影响声纹。
5. `identify` 内置双保险：阈值 0.55 + margin 0.12（第一名须领先第二名 0.12），任一不满足只给编号不给名字，并标 `suspect`。
6. **不要在同一场录音里同时入库多人**：同场向量共享信道特征，会互相拉近。一人一场、跨场累积。

## 2026-10-27 声纹模型升级：CAM++ → ERes2Net
1. **线上模型**：ERes2Net base（3D-Speaker，9.9M 参数，512 维），权重 `~/.cache/sv/eres2net_base.ckpt`（38 MB，来自 ModelScope）。
   推理环境 `~/.local/venvs/sv`（torch 2.2.2 + modelscope 1.37.1），与转录/聚类环境隔离。
   CPU 4 线程 RTF≈0.05（20 倍实时），不需要 GPU。
2. **为什么必须走 ModelScope**：GitHub 与 HuggingFace 在本机均不可达；modelscope.pipelines 缺 `datasets` 起不来，
   改为直接 import `modelscope.models.audio.sv.ERes2Net.ERes2Net` + `torchaudio.compliance.kaldi.fbank` 自行前向。
3. **库空间**：`centered-eres-v1`（512 维）。`identify` 自动检测，看到 512 维库就走桥 `embed_eres.py`。
   `enroll` 有维度护栏：往 512 维库塞 192 维向量会被直接拒绝。
4. **阈值变更**：新空间分数整体下移，弃权阈值 0.45 → **0.35**，margin 仍 0.12。
5. **实测收益**：出九↔婉辞 跨场相似度 0.419 → 0.264；真匹配 元化 0.628→0.582、恨少 0.449→0.398。
   判别余量 0.03 → **0.13**。留一场复核 T=0.35：正确 6 / 弃权 3 / 错判 0（CAM++ 最好只有 4/5/0）。
6. 流水线 step 2.5 会产出 `<base>.eres.npz`，入库用 `enroll <名> --from-eres-npz <npz> --label S?`。
